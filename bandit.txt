openssl s_client -connect localhost:30001

SSL/TLS is a system that creates a secure, encrypted tunnel between two computers.
SSL = older version (basically outdated now)
TLS = modern, secure version
People still say “SSL” casually, but they usually mean TLS
1. Encryption
Nobody in the middle can read your data.
2. Integrity
Nobody can secretly modify your data.
3. Authentication
You can confirm you're talking to the real server (not an attacker).

s_client is NOT encryption itself.
It is: a tool (program) inside OpenSSL that lets you act like a client for SSL/TLS connections.

-connect means: “connect to this server address and port”
Format: host:port
So here: localhost = your own machine 
30001 = service port

16.

 nmap -sV -T4 -p 31000-32000 localhost
Breaking it down piece by piece:

nmap
→ The program name. It's the most popular and powerful port scanner.
-p 31000-32000
→ This tells nmap: “Only scan ports from 31000 to 32000 inclusive.”
Without this, nmap would scan the first 1000 ports by default. We don’t want that — we only care about this specific range.
-sV (Service Version Detection)
→ This is very important.
After finding open ports, nmap will try to figure out what kind of service is running (for example, whether it speaks normal text or SSL/TLS).
This helps us later when we need to decide whether to use nc (for normal) or openssl s_client (for SSL).
-T4 (Timing template)
→ Makes the scan faster.
-T4 is aggressive but still safe on localhost. -T5 would be even faster but sometimes less accurate.
localhost
→ Means scan your own machine (127.0.0.1).
Since the servers are running locally, we don’t need to scan any external IP.


What will happen when you run it?
Nmap will:

Check every port from 31000 to 32000 (about 1001 ports).
Tell you which ones are open (have a server listening).
Try to detect what is running on those open ports.
